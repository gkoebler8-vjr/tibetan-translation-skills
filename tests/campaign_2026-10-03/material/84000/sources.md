# Sources and method (84000 material)

Endpoints that work (the Reading Room is now a Next.js app; the old `?ref-index=`, `.json`, `.xml` URL forms from the brief just return the HTML shell, and `/translation/tohN.html` only embeds the first slice of the translation in its page data, the rest is loaded client-side):

- **84000 GraphQL API (used for everything):** `POST https://graphql.84000.co/api/graphql` with headers `content-type: application/json` and `apollo-require-preflight: true`, no authentication; introspection is open. `work(uuid:)` returns `imprint` (Toh, section, version, publish year, Tibetan translators, Degé source description, licence name/link/description) and `titles`; `work.passages(cursor,limit,direction)` returns every passage in order (type `translation` for the translation body, with `label` such as `4.11`, `uuid`, `sort`, `content` = plain English, and `alignments[]` = `{tibetan, folioNumber, volumeNumber, toh}`); `passage(uuid:)` returns `json` (the structured English with `paragraph`/`lineGroup`/`line` nodes, which is where verse line breaks come from). The work uuid is the `workUuid` found in the translation page's embedded data; the full list of works (`works(cursor,limit){items{uuid toh title section publicationStatus imprint{...}}}`) was paged to find published texts (publicationStatus `1` or `1.a`).
- **Tibetan source view (84000's own eKangyur/eTengyur folio pages):** `https://read.84000.co/source/tohN/folio/<leaf>` (e.g. `/source/toh127/folio/13`; one page = both sides of a leaf, "F.13.a/b"). Not `?ref-index`. Tibetan is Unicode, with Derge physical line breaks.

**Which Tibetan I used.** The Tibetan in every unit is the `alignments[].tibetan` string from the 84000 API (the Tibetan span 84000 itself aligns to that English passage), i.e. 84000's own source text, not the Esukhia GitHub mirror (GitHub was not needed or consulted). I cross-checked every unit against the 84000 source-view folio pages: after stripping everything except Tibetan characters, the whole alignment string of all 34 units occurs verbatim in the concatenated source-view text of the relevant leaves (two units with a folio marker mid-word, 4.6 and 1.201, match once split at the marker, because the source view inserts its page-side header between the two halves). So no mismatch between the alignment text and the source view was found. Processing I did: (1) removed the physical line breaks (`\n`) that 84000's data keeps from the Derge lines, joining the text without adding or removing spaces; (2) for verse units only, inserted a line break after each `། །` so that padas are on their own lines (the first line of some stanzas is a speaker introduction such as "The Blessed One said", which in the Tibetan is a segment ending in `། །` of its own; it is kept as is); (3) kept the `[F.n.a/b]` folio markers inline. The raw, unprocessed alignment strings are in `sutra_raw.json`, `tantra_raw.json`, `shastra_raw.json` next to this file. Starting-side folio refs in the unit headings are inferred by tracking `[F.n.s]` markers through the whole text (marker = start of that side), so a unit with no marker inherits the side of the last marker before it.

**English.** The English is the 84000 passage text, copied verbatim; the unit text was rendered from `passage(uuid).json` (text nodes, with `lineGroup`/`line` nodes giving verse lines; footnote/endnote call-outs are not in the served text) and checked, whitespace aside, to equal the API's plain `content` string for every unit (all 34 matched). Paragraph/milestone ids given are 84000's passage `label`s (4.4, 1.14, 1.197 ...) plus uuids; the Reading Room does not expose old-style `toh127-4-4` ids. `{n}` and `{1.1.13}`-style tags are 84000's own stanza numbers. **SUTRA, Toh 127 (Samādhirāja).** Work uuid `125c3bee-621a-4c25-82bd-f8fb35093d3c`, 84000 version 1.45.37; passages 4.4-4.15 (Chapter 4), Tibetan on Degé vol. 55 leaves 12-13. 4.4-4.9 prose, 4.10-4.15 six verse stanzas ({1}-{6}). Alignment is one-to-one and clean; one point to know is that the English inserts translator-supplied numbers `[1]`-`[40]` into the list in 4.4-4.8, which the Tibetan does not have, and that the Tibetan of 4.4, 4.5, 4.6 and 4.7 ends in the middle of a list with `དང་` because the list is cut into 84000 paragraphs.

**TANTRA, Toh 381 (Emergence from Sampuṭa).** Work uuid `de1c28ce-ea8c-4058-ba5f-cda2a5e9e8a5`, version 1.12.14; passages 1.14-1.25 (Chapter 1), Degé vol. 79 leaf 74 (F.74.a-F.74.b). The text is almost entirely verse, so this span is all stanzas. Caveat found while checking alignment: in 1.11-1.13 the 84000 English (prepared with the Sanskrit edition) has two half-stanzas ("construe sound as empty, apply to smell", "construe taste as empty, apply to tactility") that are absent from the Tibetan, so the passage-level alignment there is not pada-for-pada; the span therefore starts at 1.14, where English and Tibetan stanzas correspond.

**SHASTRA, Toh 3808 (Tengyur).** 84000 has published several Tengyur works (publicationStatus 1/1.a): this one (Toh 3808, Degé Tengyur vol. 93, "Long Explanation" of the Perfection of Wisdom, Daṃṣṭrasena/Vasubandhu; translated by Gareth Sparham; work uuid `009cb40f-b705-410b-91cc-7a638ff76054`, version 1.3.4), Toh 1189 and Toh 1183 (Hevajra commentaries), Toh 3990 (very short), and others. Not published, so not retrievable as a 84000 translation with source: Toh 4150 Jātakamālā, Toh 3940 Śikṣāsamuccaya, Toh 4158 Ratnāvalī (these exist in the catalogue with status 0, i.e. no translation yet). Toh 3808 was chosen as the true treatise; passages 1.197-1.206 (leaves 33-34). It is all prose; I found no numbered verse stanzas in the whole text, so the "at least two verse stanzas" condition could not be met for the shastra. Units are 84000 paragraphs and some are long (U01 about 540 characters of English, U05 about 810) and contain several Tibetan sentences; alignment is clean (each English paragraph corresponds to exactly one Tibetan alignment string, checked by reading). Note that the Tibetan of 1.207 (not included) ends in mid-sentence, which is why the span stops at 1.206.
